# Full homepage directions — Hoàng Mỹ

These are alternative homepage systems, not three hero variations. Each keeps the same professional truth and contact routes; only the visual world, composition, pacing, and interaction language change.

## Direction 01 — Product Signal

### Core idea

The portfolio behaves like an excellent product case-study index: every claim receives nearby evidence. It is the clearest route for a recruiter or founder who needs to decide quickly, without sacrificing visual authority.

### Hero structure

- A near-black, full-height opening divided by a disciplined 12-column grid.
- Left: a large but controlled positioning statement: **Frontend specialist for React and Next.js products that work clearly and feel considered.**
- Right: a compact, structured proof rail—2.5+ years, React / Next.js focus, product-aware UI, backend-aware delivery—followed by an amber `View selected work` anchor.
- The supplied portrait appears as a quiet, tall crop below the metadata rail, not as a social-profile avatar. A thin image mask lets the architecture of the photo become material without competing with the headline.

### Full homepage structure

1. **Header** — wordmark, four text links, GitHub as an external-text link, an amber availability pin; no button cluster.
2. **Hero** — identity, proof rail, portrait, work anchor.
3. **Selected Work** — two oversized claim-and-proof chapters: MDOP first, then THÈM GÌ CŨNG CÓ. Each pairs a concise product problem/role/engineering outcome with a wide visual field; metadata is an evidence caption, never a card grid.
4. **Expertise** — three horizontal bands: Frontend Engineering, Product Interface, Full-stack Awareness. Each band uses one sentence and a small set of evidence terms rather than logos.
5. **Experience** — an asymmetrical “2.5+ years in production-oriented development” block, followed by a short account of working inside existing systems.
6. **Build · Debug · Improve** — three large verbs with specific supporting lines: new experiences, unfamiliar-codebase diagnosis, interface/system improvement.
7. **About** — portrait returns in a different crop alongside a short professional philosophy: understand the product before changing the interface.
8. **CTA** — `Need a frontend problem solved?` with email as the primary route, GitHub and LinkedIn secondary.
9. **Footer** — quiet contact repetition, location/timezone only if later supplied, and a clear `Resume — coming soon` state.

### Typography, grid, and colour

- A custom-feeling neo-grotesk display face with a highly readable humanist sans for body copy; final family selection deferred to `/impeccable typeset`.
- Strict 12-column grid, wide outer margins, dense metadata, and substantial vertical breathing room between proof chapters.
- Tinted graphite ground, warm off-white text, muted stone secondary text, and warm yellow used for selection, active anchors, and exactly one primary action per viewport.

### Selected-work presentation

Project pages read as horizontal evidence pairs rather than cards: fixed editorial label, statement of intent, then the large project frame. On desktop, the copy can become sticky while the project frame advances; on mobile, it becomes reading-first with the visual between clear text blocks.

### Motion language

Precise line reveals, section rules drawing in, and a restrained image-mask release. Project frames lift a few pixels and expose metadata on hover; touch layouts show the metadata by default. No scroll hijacking, bouncing, or decorative cursor.

### Why it fits Hoàng Mỹ

It makes the specialization unmistakable in the first seconds and treats UI taste as evidence of engineering judgment, not as a claim that he is a designer. It is the strongest all-purpose hiring and client-confidence direction.

### Potential weakness

It is intentionally more rational than cinematic. Without strong project screenshots later, visual drama must come from type, cropping, and composition rather than decorative effects.

## Direction 02 — Editorial Engineer

### Core idea

A typography-led portfolio with the confidence of an independent technical journal. The page reads as a sequence of editorial spreads about interface craft, turning engineering precision into its visual personality.

### Hero structure

- An oversized multi-line title dominates the first viewport, cut across the grid: **Interfaces with intent. Engineering with range.**
- `HOÀNG MỸ / FRONTEND SPECIALIST / REACT + NEXT.JS` appears as a small technical masthead instead of a conventional nav label.
- The portrait sits in a narrow vertical aperture at the far edge; it is revealed as the visitor scrolls, keeping the face personal but not central to the professional statement.
- One warm-yellow inline action—`Read the work`—interrupts the display type like an editor’s mark.

### Full homepage structure

1. **Header** — masthead-style name, low-profile navigation, and a small `available for thoughtful work` status line.
2. **Hero** — typographic thesis, aperture portrait, anchor link.
3. **Selected Work** — MDOP and THÈM GÌ CŨNG CÓ become two editorial “issues”: huge sequential numbers, a full-bleed frame, a short deck, and a margin column for stack/role/focus.
4. **Expertise** — a typeset field of capabilities, grouped by meaning, where key phrases lock into the grid rather than appearing as tags.
5. **Experience** — a folded-page composition: 2.5+ years, production experience, then a brief paragraph about working in both new and existing codebases.
6. **Build · Debug · Improve** — three oversized lines that unfold into concrete behaviour on focus/hover; keyboard access reveals the same descriptions.
7. **About** — a measured two-column note with the full portrait in an off-centre crop and a working-style statement.
8. **CTA** — an editorial closing page: `If the interface carries the product, let’s make it carry its weight.` Email is set at display scale.
9. **Footer** — compact colophon with GitHub, LinkedIn, contact, copyright, and `Resume / TBD`.

### Typography, grid, and colour

- Strong display typography is the principal image. A distinctive, contemporary display family is paired with a pragmatic UI/body face and tabular metadata; final faces arrive after the direction is locked.
- Baseline-driven editorial grid with deliberate asymmetry: broad text fields, narrow annotation columns, full-bleed image breaks, and occasional dense pages following quiet ones.
- Tinted charcoal, soft ivory, and warm yellow. Yellow behaves like annotation ink—a selected phrase, rule termination, or link—not an ambient glow.

### Selected-work presentation

Each project is a long-form spread, not a product tile. The visitor encounters context, visual system, interaction reasoning, and engineering evidence in a controlled reading sequence. MDOP leans into conversion-flow reasoning; THÈM GÌ CŨNG CÓ uses food-first imagery and mobile composition as its narrative proof.

### Motion language

Text masks release on first view; margin notes enter on a slight stagger; frames slide through a clipped aperture. Motion feels like turning or setting a printed spread: clean easing, no kinetic type for its own sake.

### Why it fits Hoàng Mỹ

It gives interface sensitivity equal weight with frontend engineering and makes the site feel authored rather than assembled. It is particularly memorable for agency, design-aware team, and premium product audiences.

### Potential weakness

It asks visitors to read a little more. The layout must preserve a very direct first-screen role statement so a time-pressed recruiter does not mistake it for a creative portfolio first and an engineering portfolio second.

## Direction 03 — Kinetic Casebook

### Core idea

The homepage is a controlled sequence of project environments. Work leads, while GSAP provides cinematic transitions that explain change of state, selection, comparison, and conversion—not decorative spectacle.

### Hero structure

- A full-viewport, dark stage with a large typographic positioning line anchored low left.
- A dynamic “work reel” occupies the right two-thirds: MDOP and THÈM GÌ CŨNG CÓ fragments alternate in large masked panels; the supplied portrait appears briefly as a human interlude, never as a floating profile card.
- A static accessibility-safe text introduction is present in the DOM from first paint; motion enhances it after load rather than hiding the core message.

### Full homepage structure

1. **Header** — transparent over the stage, becomes solid tinted-black on scroll; text navigation and an unobtrusive contact marker.
2. **Hero** — positioning, project reel, `Explore work` action, availability/contact information.
3. **Selected Work** — two cinematic chapters. Each begins with a near-full-width visual panel, then resolves into project facts: context, role, stack, product reasoning, interactions, and engineering considerations.
4. **Expertise** — a horizontal composition of three “capability tracks” that progresses with scroll but also reads as ordinary stacked content with motion disabled.
5. **Experience** — a grounded pause after the image-heavy work: concise proof of professional experience and cross-functional delivery.
6. **Problem Solving** — an interactive but non-essential flow diagram: Understand → Diagnose → Build → Improve. Selecting a stage exposes an actual example of the working method, not invented case metrics.
7. **About** — a quiet portrait-and-copy reset with no animation beyond a fade; it restores human scale after the project sequence.
8. **CTA** — high-contrast email invitation, then GitHub and LinkedIn; the language invites a project build or existing-system improvement.
9. **Footer** — dark technical close with social routes, pending-resume status, and an optional small back-to-top link.

### Typography, grid, and colour

- A compact, high-impact display face sits against calm body copy and technical labels; type is scaled for cinematic framing without compromising responsive readability.
- Fluid grid: full-bleed visual stages alternate with aligned content bands, while a persistent left guide carries section numbers and current context on larger screens.
- Tinted black, warm off-white, and one controlled yellow beam/selection state. Project worlds may briefly tint their own image frame but must return to the shared portfolio palette.

### Selected-work presentation

MDOP can dramatize finder, compare tray, state persistence, and conversion CTA as consecutive visual states. THÈM GÌ CŨNG CÓ counterbalances it with food-first mobile flow, menu intent, and store-finder hierarchy. Both retain concise factual text so the experience stays credible if media is delayed or unavailable.

### Motion language

GSAP masks, synchronized project transitions, controlled depth shifts, and a small amount of parallax. The page uses native scrolling, short transform/opacity animations, lazy-loaded media, and a reduced-motion mode that swaps every sequence for immediate static content.

### Why it fits Hoàng Mỹ

It directly demonstrates that he can make frontend interactions feel polished and intentional—the important **how it feels** part of his positioning—while selected work remains the centre of gravity.

### Potential weakness

It has the tightest performance and asset-quality budget. It should be chosen only if the final build will have strong MDOP/restaurant project media or carefully authored visual substitutes.
